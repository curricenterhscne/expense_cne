## Phase 2 — 데이터 계층 (1.5일)

가장 중요한 단계입니다. 문제 1·2·4가 여기서 해결됩니다.

### 작업

1. `gas/Courses.gs` — `getCourses()`
   - 헤더 공백 무시 부분 일치 매칭 (기존 `findCol()` 방식 계승)
   - **응답에서 `교사연락처` 제외**
   - `수강인원`이 숫자로 변환되지 않으면 `unavailable: true` 플래그와 사유를 붙여 반환 → 프런트에서 선택 불가 처리
   - 제출 여부(`submitted: true/false`)를 함께 반환 → 교사가 자기 강좌의 제출 상태를 폼 진입 전에 확인
2. `gas/Submit.gs` — `submitApplication()`
   - `신청내역` 시트가 없으면 헤더와 서식을 갖춰 생성
   - `접수상태` 열에 데이터 유효성 검사(`미접수`/`접수`/`보류`) 자동 설정
   - **upsert**: `강좌코드`로 기존 행 검색 → 있으면 갱신, 없으면 추가
     - 유지: `접수번호`, `최초제출일시`, `접수상태`
     - 갱신: `최종수정일시`, `수정횟수`+1, 그 외 전 항목
   - `접수번호`는 `PropertiesService` 기반 독립 시퀀스
   - 서버 측 재검증 — 한도(`수강인원 × 단가`) 초과, 항목 10개 초과, `설정`의 `접수상태`가 `마감`이면 거부
   - `LockService`로 감싸기
3. 26-1 데이터 일부를 테스트 시트에 넣고 upsert 동작 확인

### 완료 조건

- [ ] 같은 강좌로 3회 제출 → 행이 1개만 존재, `수정횟수`가 3
- [ ] 재제출 후에도 담당자가 `접수`로 바꿔 둔 값이 유지됨
- [ ] `courses` 응답에 연락처 문자열이 존재하지 않음
- [ ] 한도를 넘는 payload를 직접 POST해도 서버가 거부
- [ ] `접수상태`가 `마감`일 때 제출 거부

## Phase 4 — 프런트엔드 이식 (1.5일)

기존 `legacy/index.html`의 UI와 UX는 완성도가 높으니 **디자인을 새로 만들지 말고 그대로 이식**합니다.

### 작업

1. 990줄 단일 파일을 분리
   - `docs/index.html` — 마크업만
   - `docs/css/style.css` — 기존 `<style>` 이관
   - `docs/js/` — 기능별 6개 파일
2. 화면 흐름 재구성
   ```
   [강좌 선택] → [뒷 4자리 인증] → [신청 폼] → [확인] → [완료·인쇄]
   ```
3. 신규 UI 요소
   - 강좌 선택 시 제출 완료 강좌에 `✓ 제출됨` 표시
   - 기존 신청이 있으면 "수정 제출" 모드로 진입, 상단에 안내 배너
   - `수강인원` 오류 강좌는 선택 불가 + 담당자 연락처 안내
   - 접수 마감 시 폼 대신 마감 안내 화면
4. jsPDF CDN 제거

### 완료 조건

- [ ] 각 JS 파일 300줄 이하
- [ ] 기존 UI와 시각적으로 동일
- [ ] 외부 CDN 참조 0개
- [ ] 수정 제출 흐름이 화면상 명확히 구분됨
